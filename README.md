# StarAPI Router

> 本地优先的统一 AI API 网关：把多个 AI 服务、账号和模型集中到自己电脑上的一个地址，用一把统一 API Key 接入客户端。

StarAPI Router 运行在 Windows 本机。你在管理面板中配置上游服务、账号、模型和密钥，客户端只需要访问本地接口，不必分别保存每个上游的凭据。所有功能以你下载的具体版本和 Release 说明为准。

## 功能总览

下面列出当前公开版本面向用户提供的主要功能，以及它们解决什么问题、如何使用。

### 1. 客户端管理中心

- **作用**：集中查看可接入的客户端类型、接入平台和所需参数，避免每次重新查找 Base URL、API Key 和模型填写方式。
- **使用方法**：启动 StarAPI Router 后打开管理面板，进入“客户端”或客户端管理中心，选择要接入的客户端/平台，按页面提示复制本地 Base URL、统一 API Key 和模型名称，再粘贴到客户端的接口设置中。
- **安全边界**：客户端只保存本地统一 Key；上游服务的真实 Key 留在 StarAPI Router 本机。

### 2. 统一本地 API 网关

- **作用**：给不同客户端提供一个稳定的本地入口，把请求转发到已启用的上游模型。
- **使用方法**：默认 Base URL 为 `http://127.0.0.1:1991/v1`；在客户端填写管理面板生成的统一 API Key，并选择面板中已启用的模型。

### 3. 多服务、多账号和平台接入

- **作用**：把多个兼容的 AI 服务、订阅账号和 API 账号集中管理；不同客户端通过同一个本地入口使用。
- **可接入范围**：支持兼容常见 AI API 协议的云端服务，也支持 OAuth 登录、认证文件以及本地模型服务。
- **使用方法**：进入“供应商/账号”管理，新增服务地址和凭据；如果平台支持 OAuth，则进入 OAuth 页面完成登录；保存后到套餐或模型页面启用可用模型。

### 4. 套餐与多密钥管理

- **作用**：将模型、账号和访问权限按套餐组织起来；一个 StarAPI Router 实例可以创建多个套餐，每个套餐可以配置多把密钥。
- **使用方法**：进入“套餐”页面新建套餐，添加模型和认证账号，再为套餐添加一把或多把密钥；通过路由策略决定多个可用账号如何承接请求。
- **适用场景**：区分不同客户端、团队成员或不同服务额度，单独停用某把密钥不会影响其他套餐。

### 5. 代理设置

- **作用**：让 StarAPI Router 访问上游服务时通过指定的网络代理，解决网络环境或出口线路问题。
- **支持方式**：全局出站代理支持 HTTP、HTTPS 和 SOCKS5；也可以按套餐或认证文件单独设置代理。
- **使用方法**：进入“设置”配置全局代理，保存后上游请求默认经过该代理；需要例外时，在套餐编辑或认证文件设置中填写单独代理。

### 6. 模型启用、停用和路由控制

- **作用**：控制哪些模型可以被客户端看到和调用，不用修改客户端配置即可临时下线某个模型。
- **使用方法**：在套餐或模型管理中添加上游真实模型名、设置展示别名并切换启用状态；停用后模型不再作为可用路由。
- **请求分配**：多个套餐或多把密钥同时可用时，可选择轮询、加权轮询或优先填满等路由策略，并结合重试、冷却状态提高可用性。

### 7. 视觉模型独立开关与单独调用

- **作用**：把视觉模型作为独立能力管理；需要图片理解时才启用和调用，不影响普通文本模型。
- **使用方法**：在视觉设置中配置视觉模型，单独切换视觉路由开关；可按全局策略使用，也可按模型覆盖。图片请求需要目标模型和视觉模型均按页面提示正确配置。
- **注意**：未配置或未启用视觉模型时，不要假定普通文本模型能够处理图片。

### 8. 本地模型接入：llama.cpp 与 Ollama

- **作用**：把本机运行的模型接入统一 API，不必把所有请求发送到云端。
- **llama.cpp 使用方法**：在本机启动或指定现有的 llama-server，或按配置让 StarAPI Router 管理启动；在本地模型设置中填写服务地址、模型标识和所需参数。
- **Ollama 使用方法**：先启动 Ollama 服务，再在本地模型设置中以 Ollama 类型添加服务地址和模型名；保存并启用后，从客户端用统一 Base URL 调用。
- **注意**：本地模型的实际速度、上下文长度和显存/内存占用取决于本机硬件与模型配置。

### 9. 常见 API 协议适配与流式响应

- **作用**：将客户端常见的对话、响应和消息请求转换为对应上游需要的格式，并把流式输出持续转发给客户端。
- **使用方法**：客户端按客户端管理中心提供的本地 Base URL 接入；通常不需要为每个上游单独修改协议设置。

### 10. 思考/推理内容处理

- **作用**：统一处理支持的 thinking、reasoning 等字段，在不同上游协议之间进行适配，尽量保留可展示的推理输出。
- **使用方法**：选择支持推理的模型并按面板/模型要求开启相应选项；具体输出取决于上游模型和客户端是否支持显示。

### 11. OAuth 登录与认证文件管理

- **作用**：通过 OAuth 登录接入支持该方式的平台，并集中保存和管理认证文件；避免手工复制临时令牌。
- **使用方法**：进入 OAuth 页面，选择平台并完成浏览器授权；完成后在“认证文件”页面查看认证状态、绑定账号和可用模型信息。
- **安全边界**：认证文件属于私密数据，只保存在本机，不能上传到 Issue、公开仓库或截图中。

### 12. 配额与可用模型查询

- **作用**：查看每个认证文件或账号的剩余配额、状态以及它拥有/可使用的模型，便于选择正确的路由。
- **使用方法**：进入“配额用量”或认证文件详情，刷新对应账号信息；配额和模型列表以平台实时返回结果为准，平台不提供信息时页面可能无法显示完整数据。

### 13. Skill 统一管理

- **作用**：集中扫描、导入、启用或停用本机 Skill，并为不同客户端工作区统一管理 Skill 配置，减少重复复制。
- **使用方法**：进入 Skill 管理中心扫描可用目录，导入需要的 Skill，选择工作区或客户端目标并切换启用状态；操作前请确认 Skill 来源可信。

### 14. MCP 统一仓库管理

- **作用**：集中登记、查看和管理 MCP 服务仓库/配置，让多个客户端使用统一维护的 MCP 信息。
- **使用方法**：进入 MCP 管理中心添加或导入仓库配置，检查服务地址和工具列表后启用；不使用的服务及时停用，避免向不可信服务发送数据。

### 15. 模型别名与模型列表

- **作用**：请求仍使用上游实际接受的模型名，同时在管理面板和客户端模型列表中显示更容易识别的别名。
- **使用方法**：编辑模型时填写真实模型名和展示别名，保存后通过本地 `/v1/models` 检查客户端可见列表。

### 16. 用量、Token 与成本统计

- **作用**：自动统计模型请求次数、输入 Token、输出 Token、总用量和成本估算，帮助你了解哪个模型消耗最多。
- **使用方法**：进入“用量统计/配额用量”页面按时间、模型或账号查看记录；成本是根据已配置价格和上游返回数据计算的估算值，不等同于平台最终账单。

### 17. 诊断与健康检查

- **作用**：快速区分本地服务未启动、模型列表配置错误、认证失效和真实请求失败等问题。
- **使用方法**：依次检查本地服务、`/v1/models` 模型列表和真实请求探测；根据返回状态和错误信息修正供应商、模型、代理或认证配置。

### 18. 一键更新与版本检测

- **作用**：客户端联网后检查公开 Release 的最新版本，有新版本时提示用户更新，减少手工寻找下载地址的步骤。
- **使用方法**：在客户端的“检查更新/版本信息”入口执行检查；确认版本和校验值后下载并安装/替换对应公开包。更新必须从本仓库的公开 Release 获取，并先校验 SHA-256。
- **说明**：更新提示是否出现取决于当前客户端版本是否包含更新检查功能、网络是否可用以及公开 Release 是否存在更新版本。

## 工作方式

```text
客户端管理中心 / 兼容 AI 客户端
              |
              v
http://127.0.0.1:1991/v1 + 统一 API Key
              |
              v
StarAPI Router（你的电脑）
       |          |           |
       v          v           v
 云端上游服务   OAuth账号   本地模型服务
                         （llama.cpp / Ollama）
```

## 下载、校验与启动

1. 打开[最新公开版本](https://github.com/StarAI-2026/starapi-router/releases/latest)。
2. 按你的系统选择对应的包（`<版本号>` 以 Release 页面实际文件为准）：

   | 系统 | 机型 | 下载文件 |
   |------|------|----------|
   | Windows | 常见电脑（Intel/AMD） | `StarAPI_<版本号>_windows_amd64.zip` |
   | Windows | ARM 设备（骁龙笔记本等） | `StarAPI_<版本号>_windows_aarch64.zip` |
   | macOS | Apple Silicon（M 系列） | `StarAPI_<版本号>_darwin_aarch64.tar.gz` |
   | macOS | Intel 机型 | `StarAPI_<版本号>_darwin_amd64.tar.gz` |
   | Linux | x86_64 | `StarAPI_<版本号>_linux_amd64.tar.gz` |
   | Linux | ARM64 | `StarAPI_<版本号>_linux_aarch64.tar.gz` |
   | Linux（musl/OpenWrt） | 对应架构 | `StarAPI_<版本号>_linux_<架构>_no-plugin.tar.gz` |

3. 在 PowerShell 中校验（以 Windows amd64 为例）：

   ```powershell
   Get-FileHash .\StarAPI_<版本号>_windows_amd64.zip -Algorithm SHA256
   ```

   将显示的 SHA-256 与同一 Release 页面 `checksums.txt` 中同名文件的值逐字比对，一致后再运行。
4. 解压到有写入权限的目录，运行 `starapi-router.exe`（Windows）或 `./starapi-router`（macOS/Linux）。
5. 打开管理面板：`http://127.0.0.1:1990` 或 `http://127.0.0.1:1991/panel/`。

> 公开仓库提供各平台便携运行包，不是安装程序；公开仓库不提供产品源代码。Linux `no-plugin` 版本不支持动态库插件，面向 musl 或老系统。

## 首次配置

1. **启动服务**：运行 `starapi-router.exe`，等待本地服务启动。
2. **添加上游或本地模型**：在供应商、OAuth 或本地模型页面完成配置。
3. **创建套餐和模型**：新建一个或多个套餐，添加实际模型名，按需要设置别名、代理和启用状态。
4. **添加多把密钥**：在套餐中添加一把或多把密钥，按需要设置权重和路由策略。
5. **生成统一 Key**：在统一接口/密钥管理页面生成供客户端使用的本地 Key。
6. **接入客户端**：在客户端管理中心选择平台，填写：

   ```text
   Base URL: http://127.0.0.1:1991/v1
   API Key:  你生成的统一 API Key
   Model:    管理面板中已启用的模型
   ```
